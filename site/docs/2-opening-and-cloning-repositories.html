2. Opening and cloning repositories

I want to … Do this
Open a repository already on my computer Open repository… on the home screen, or Ctrl+O, then pick the folder. Any folder inside a repository works; the app finds the top.
Download a repository from a server Clone…, paste the URL, choose the destination folder, press Clone. A progress bar shows the download.
Clone including submodules Leave Clone submodules too ticked (default).
Reopen something I used before Click its card under Bookmarks on the home screen, or use the command palette (Ctrl+K).

Opening repositories safely

A folder handed to you with its own .git can carry settings or scripts that make Git run programs on your computer. Treeline protects you in a few ways:

  • Only folders you opened. Treeline works only on folders you chose with Open repository… or Clone…, folders you opened before (they come back when you restart), and folders inside those (a submodule, for example). Anything else is refused with “That folder has not been opened in Treeline.” A whole drive cannot be opened as a repository.
  • “This repository can run programs.” The first time you open a folder whose own settings or hooks can run programs, a window lists what it found: hook scripts, core.hooksPath (used by tools such as husky), core.sshCommand, filter, merge or diff drivers, credential helpers that run a program, signing programs, or an included settings file. Nothing in the repository has been run at that point.
    • Open anyway opens it and remembers your answer for that folder. Closing the window opens nothing.
    • Open only folders you made yourself or got from a source you trust. Git LFS and ordinary credential helpers (manager, osxkeychain) are normal and do not trigger the window. If the check itself could not run, you are asked in the same way.
  • Always off. For its own Git calls Treeline switches off two settings that would run a program just by looking at a repository: core.fsmonitor and external diff programs (and text-conversion drivers when showing a diff). In ordinary repositories you will notice nothing; in a very large repository that relies on Git's built-in file-system monitor, refreshing can be a little slower.
  • Cloning. A destination you choose with Browse is trusted. If you type the destination instead, a window of the operating system asks you to confirm “Clone … into …” first.

If a clone succeeds but a submodule can't be downloaded (for example no access to it), the repository still opens and a message explains what to do; the submodule appears greyed-out in the sidebar and can be initialised later.
