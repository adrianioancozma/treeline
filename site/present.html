Treeline

A fast Git client for any provider.

Use ← → or Space to move · F full screen · Home/End

The problem

  • Everyday Git clients slow down and crash with many repositories open.
  • Our repositories are large, have submodules, and often live in synced folders.
  • When Git fails, the message is a wall of text — no explanation, no next step.

What we set out to build

  • Fast — instant tab switching, smooth history on 10,000+ commits.
  • Any provider — no accounts, no integrations; just Git.
  • Tabs, bookmarks, clone, submodules — the daily essentials, done well.
  • A clear interface — and errors that explain themselves.

How it works

React + TypeScriptThe interface: tabs, graph, diffs, dialogs.
Tauri + RustA small native shell. Runs every Git call off the UI thread.
Your gitExactly the Git you already use — so every remote and hook just works.

It never stores credentials. Sign-in is your normal credential manager or SSH key.

Fast where it counts

60–420 msstatus on 10k-commit repos
~210 msfirst 400 commits
2–3×faster submodule listing
  • Refresh runs in parallel; only the active tab is watched.
  • History is virtualised and loaded in pages.
  • Read-only commands never touch the index — no refresh loops.

Measured on large production repositories; results vary by machine.

See the whole story

  • Commit graph with branches, tags and merges
  • Click a branch to highlight its history
  • Search, per-commit diffs, right-click actions

Stage exactly what you mean

  • File, hunk, or individual lines
  • Commit, amend, commit & push
  • Discard is always confirmed

Conflicts, calmly

  • Pick ours, theirs or both for each conflict
  • Edit the result, mark resolved, continue
  • Abort any time — nothing is lost

Tidy history

  • Interactive rebase from a simple list
  • Reword, squash, fixup, edit, drop, reorder
  • Local changes stashed and restored automatically

Errors that help

  • What happened, why, and how to fix it
  • One-click fixes where possible
  • Force options offered last, explained, and confirmed

Force, with guardrails

  • Never automatic
  • Uses force-with-lease
  • States what will be lost before you confirm

Built to be trusted

  • 50 automated tests, including integration tests that run real Git operations.
  • Independent code review found 11 issues — all fixed and covered by tests.
  • Verified end to end in the running app: clone, stage, commit, push, rebase, conflicts.
